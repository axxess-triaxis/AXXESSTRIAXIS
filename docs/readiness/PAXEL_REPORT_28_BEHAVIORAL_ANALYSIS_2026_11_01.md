## The practice rules in full

These are adopted as a standing rule in `CLAUDE.md` ("Paxel 9.5 Practice Standards -- Standing Rule").

1. **Error closure.** Before a session ends, every error it hit (failed test, failed command, failed build, runtime
   error) is either fixed and re-run, or written down with an ID and a named owner in the closeout or
   `docs/readiness/ACTIONABLES_READINESS_MATRIX.md`. "Pre-existing" is allowed only with a citation.
2. **Live check before "done".** A deploy is not done when the workflow is green or Vercel says "ready". The closeout
   records an independent live check (URL, status, timestamp) against the deployed SHA, as already required by
   `docs/readiness/CLOSEOUT_TEMPLATE.md`. Where that needs a credentialed console, it is handed to the founder and the
   status stays not verified.
3. **Regression test first.** A bug fix starts with a test that reproduces the bug and fails, then passes after the
   fix. Where no test is possible, the closeout says why.
4. **No bare retries.** A retry instruction says what failed, the current hypothesis, and what success looks like
   ("The build failed on X; I think Y; rerun and confirm Z"). This applies to the founder's prompts and to Codex
   prompts alike; an agent that receives a bare retry restates the failure and its hypothesis before acting.
5. **Acceptance criteria up front.** Every session or sprint prompt states what done looks like, in checkable terms.
6. **Outcome closure.** Every Decision Ledger entry and every product insight gets an Outcome, or
   `Pending, review by <date>` (no more than 14 days out). A weekly pass closes or re-dates Pending rows with the
   observed result. Outcomes are never invented or inferred.
7. **Plan-first target 95%.** The existing plan-first rule stays; the target is now explicit. Exceptions are still
   declared, as the existing rule requires.
8. **Sessions in the repo's own folder.** Work on another repository (callismatic, STILL, port4lleo and others) runs
   in a session started in that repository's own checkout, so its sessions and commits are attributed to it.
9. **Parallel work is isolated.** Parallel agents each get their own worktree, a written brief with acceptance
   criteria, and end in their own PR.
