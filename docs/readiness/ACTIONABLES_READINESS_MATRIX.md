## Operating Rules

Every actionable must be reviewed after every sprint.

An actionable can be marked `Yes` only if all of the following are true:

- Implementation exists.
- Verification evidence exists.
- The relevant user journey works or the external blocker is documented.
- Documentation is updated.
- Confidence is at least 80%.

If implementation exists but live proof does not, status remains `No`.

## P0 Correction: Public Entry Split (2026-07-24, HITL "Attempt 4")

**Root-caused and fixed.** The two-sprint-old "Investor Preview's Continue to workspace is broken" / "root domain lands on a stale, dead-end authenticated-looking page" defects (first flagged in the Sprint 1 pre-work walkthrough above, never previously root-caused) were reproduced live by the HITL and diagnosed to a precise mechanism: `/auth`'s "already authenticated" branch treated a demo/investor mock session (`source: "mock-rbac"`, set by clicking "Open investor preview") exactly like a real one, so a visitor who had ever opened Investor Preview in a browser saw "Signed in as Ananya Rao" on every future `/auth` visit regardless of intent -- including a genuine "Sign In" click from the public site. Separately, the demo-mode `localStorage` flag never expires while its edge-visible cookie counterpart expires after 12 hours; once that gap opened, the client rendered "Signed in" while the edge middleware bounced navigation back to `/auth`, making "Continue to workspace" appear completely dead.

Fixed by: (1) splitting public entry into two dedicated, non-overlapping routes -- `/investor` (isolated investor-demo entry, establishes its own demo session, never shares state with real sign-in) and `/landing` (beta workspace entry, unconditionally clears any stale demo state on load and only ever treats a genuine Supabase-backed session as "already signed in"); (2) self-healing the cookie/localStorage desync by refreshing the edge-visible demo cookie on every app load while demo mode is active. Full detail: `docs/readiness/P0_PUBLIC_ENTRY_INVESTOR_BETA_SPLIT_2026_07_24.md`. This does not change any numbered actionable's status (no A-XX ID was ever assigned to this defect -- it was tracked only as an unlabeled Known Blocker); it closes a real, previously-reproduced production defect.
