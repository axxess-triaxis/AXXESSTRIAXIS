# Next.js 16.3.5 RCE Alert Fix -- Closeout, 2026-09-27

Ledger: `FOUNDER_BUG_CLOSURE_LEDGER_2026_07_31.md` item #73.
Branch: `fix/next-16.3.5-rce-alerts` (from `origin/main` `68ca465`).

## External Signal

A RepoWatch org audit run on 2026-09-27 found 4 open Dependabot alerts on AXXESSTRIAXIS. Two of them are critical, both against `next`:

| Alert | Advisory | Summary | Vulnerable | First patched (16.x) |
|---|---|---|---|---|
| #120 | GHSA-p293-qw3h-jr36 | Unauthenticated RCE on Windows-hosted servers | `>=16.0.0 <16.3.3` | 16.3.3 |
| #121 | GHSA-2xp9-vwfh-vxw4 | Unauthenticated RCE in the Image Optimization API when AVIF files are used | `>=16.0.0 <16.3.3` | 16.3.3 |

There is no 16.2.x backport.

## Root Cause

`pnpm-workspace.yaml` `overrides:` exact-pinned `next: 16.2.12` and `eslint-config-next: 16.2.12`. Those pins were added in PR #221 (`RELEASE_AGE_GATE_AND_BUILD_INCIDENT_CLOSEOUT_2026_08_12.md`) as "held-stable" pins, after `next@16.3.0` broke the build and `eslint-config-next@16.3.0` broke lint. An override wins over the `package.json` range. As a result:

- Production resolved `next@16.2.12`.
- Dependabot PR #377 (`next` `^16.3.1` -> `^16.3.3`) changed only the `package.json` range. Its lockfile still resolved `next@16.2.12`, so merging it would not have closed either alert.
- #377's Vercel preview also failed `pnpm install --frozen-lockfile` with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`. The failing packages were `baseline-browser-mapping@2.11.26`, `browserslist@4.29.1`, `minimizer-webpack-plugin@5.12.0` and `webpack-sources@3.5.3`, all published on 2026-09-24.

## What Changed

- `pnpm-workspace.yaml`: `next` and `eslint-config-next` overrides changed from `16.2.12` to `16.3.5`, with an inline comment citing #120/#121. 16.3.5 (published 2026-09-11) is the newest release past the 7-day `minimumReleaseAge` gate. 16.3.6 (published 2026-09-22) only clears the gate on 2026-09-29.
- `package.json`: `next` range changed from `^16.3.1` to `^16.3.5`.
- `pnpm-lock.yaml`: re-resolved with a targeted `pnpm install`. A full `pnpm clean --lockfile` regeneration was not needed: changing an existing override's value re-resolves, unlike adding a new override (the constraint recorded in the 2026-08-12 closeout). The lockfile package delta against `main` is:
  - `next` and the `@next/*` family (`env`, `eslint-plugin-next`, 8 `swc-*` binaries): 16.2.12 -> 16.3.5
  - `eslint-config-next`: 16.2.12 -> 16.3.5
  - `@swc/helpers`: 0.5.15 -> 0.5.23
  - `@eslint-community/eslint-utils` 4.9.1: added
  - `baseline-browser-mapping` 2.11.21: removed (deduplicated to the existing 2.11.25)

  Every added version was checked with `npm view <pkg> time`: all were published before the 7-day cutoff. No other direct dependency changed.
- `next-env.d.ts`: Next 16.3.5's generated type-reference file adds `import "./.next/types/root-params.d.ts";`. This file is generated by `next build`, not hand-edited.
- `src/app/App.tsx`, `src/features/auth/EnterpriseAuthFlowPage.tsx` (x2), `src/features/settings/SettingsSection.tsx`, `src/features/stakeholders/StakeholdersSection.tsx` (x2): the new `eslint-config-next` rule `@next/next/no-location-assign-relative-destination` flagged 6 pre-existing `window.location.assign()` calls. The founder decided in-session to suppress them per line with `eslint-disable-next-line ... -- <reason>`, so behavior is unchanged. At least `SettingsSection.tsx` relies on a full reload on purpose.
- `docs/readiness/FOUNDER_BUG_CLOSURE_LEDGER_2026_07_31.md`: item #73 added, plus a line under open items.
